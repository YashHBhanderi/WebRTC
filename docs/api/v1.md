# SpreeWe API v1

Machine-readable spec: [`openapi.yaml`](./openapi.yaml). It is generated from the route definitions in `webrtc-BE/src/api/v1/routes.ts`, the same definitions the server uses to validate requests. A test fails if the committed file differs from the code.

To regenerate it, run `cd webrtc-BE && npm run openapi`. This builds to `dist/` first. The tests can also write it: `OPENAPI_WRITE=1 npx vitest run test/api-v1.test.ts`.

## Versioning

- Base path `/v1` (also `/api/v1` behind nginx). Legacy routes are unchanged and still served.
- Within v1, changes are additive only (new endpoints, new optional fields). Breaking changes go to `/v2`, with v1 kept for a published deprecation period.

## Authentication and context

- `Authorization: Bearer <Clerk session token>` on **every** `/v1` route. The router applies authentication before routing, so a new `/v1` route cannot be public by accident, and unknown `/v1` paths answer `401` before `404`.
- The **workspace** is the active organization in the session token. No endpoint accepts a tenant id. With no active organization you are in the global context.
- Endpoints marked `x-requires-workspace` answer `400` in the global context.
- **Membership revocation is immediate.** A token issued before your membership was removed gets `403`.
- This version has no API keys and no developer applications; those are later phases.

## Responses

Success:

```json
{ "data": { } }
```

Paginated success:

```json
{ "data": [ ], "page": { "nextCursor": "6ad7…" } }
```

Error (all failures):

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "The request is invalid",
             "details": [ { "path": "limit", "message": "must be <= 100" } ] } }
```

| Status | `code` | When |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Invalid params, query or body (`details` lists fields); unknown body fields; workspace required |
| 401 | `AUTHENTICATION_ERROR` | Missing or invalid session |
| 403 | `PERMISSION_ERROR` | Role or policy forbids it; membership removed; workspace suspended or deleted |
| 404 | `NOT_FOUND_ERROR` | Doesn't exist **or is not visible in your context**. Other workspaces' resources are never confirmed with a 403 |
| 429 | `RATE_LIMIT_ERROR` | Rate limit exceeded |
| 500 | `SERVER_ERROR` | Unexpected; details are logged, never returned |

## Pagination and filtering

- `?limit=` from 1 to 100 (default 20). `?cursor=` takes the opaque `page.nextCursor` from the previous page. `nextCursor: null` means there are no more pages.
- Only documented query parameters are accepted; unknown ones are rejected. Text filters are length-capped and regex-escaped.

## Rate limits

- **All routes:** per-IP global limit (`RATE_LIMIT_MAX`, default 600/min).
- **Routes marked `x-rate-limit: sensitive`:** an extra stricter limit (`RATE_LIMIT_SENSITIVE_MAX`, default 60/min).
- Responses carry `RateLimit` / `RateLimit-Policy` headers (draft-7).
- Counters are **in memory per process** (see the limitations in the Phase 4A report).

## Endpoints

| Method | Path | Notes |
| --- | --- | --- |
| GET | `/v1/me` | Profile and active context |
| GET | `/v1/workspace` | Workspace required |
| PATCH | `/v1/workspace/policies` | Owner or admin; sensitive; boolean fields only, at least one |
| GET | `/v1/workspaces` | Workspaces you've used |
| GET | `/v1/directory` | Paginated, `?q=`; no emails |
| GET | `/v1/conversations` | Paginated, newest first, includes `scope` and `external` |
| GET | `/v1/conversations/{id}/messages` | Paginated, newest first; 404 if not visible |
| POST | `/v1/conversations/external` | Workspace required; sensitive; policy-gated |
| GET | `/v1/calls` | Paginated call history, `?filter=` |
| GET | `/v1/recordings/{id}` | Short-lived signed links; 404 if not visible |

## Examples

```http
GET /api/v1/conversations?limit=2
Authorization: Bearer eyJ…

200 OK
{ "data": [ { "_id": "6ad7…e590", "isGroup": false, "name": "", "scope": "tenant", "external": false,
              "memberCount": 2, "createdAt": "2026-10-20T12:00:00.000Z" } ],
  "page": { "nextCursor": null } }
```

```http
PATCH /api/v1/workspace/policies
Authorization: Bearer eyJ…   (session with role org:member)
{ "allowExternalChat": true }

403 Forbidden
{ "error": { "code": "PERMISSION_ERROR", "message": "Only workspace owners and admins can change policies" } }
```

```http
GET /api/v1/conversations/<id in another workspace>/messages
404 Not Found
{ "error": { "code": "NOT_FOUND_ERROR", "message": "Conversation not found" } }
```

## Tests

`test/api-v1.test.ts`:
- Every registered route under both prefixes rejects unauthenticated requests with the v1 envelope.
- Validation errors carry field details.
- Workspace and role checks, including the mass-assignment guard.
- Cross-workspace and global-context 404s.
- Cursor pagination, directory without emails, recordings.
- Revoked membership.
- The OpenAPI document matches the registry and the committed file (and round-trips through a YAML parser).
